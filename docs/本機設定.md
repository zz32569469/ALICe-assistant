# 本機設定 `alice.local.json`

每台電腦各有一份，放在 repo 根目錄，不進版控。

- **怎麼產生：** `node scripts/setup.cjs`（或 `scripts/setup-kb.cjs`）會產生只含知識庫的最小設定。其他專案照 `alice.local.example.json` 補上。
- **改完要做的事：** 跑 `node scripts/doctor.cjs` 檢查，再重啟 Core 才會生效。

## 根層

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `knowledgeBase.path` | 是 | 知識庫（Obsidian vault）的資料夾 |
| `knowledgeBase.summaryPage` | 是 | 艾莉絲每次回覆前讀的摘要頁（vault 相對路徑） |
| `knowledgeBase.rolesDir` | 是 | 角色頁的資料夾（vault 相對路徑）。部下照 `projects[].role` 找同名的角色頁 |
| `codex.available` | 是 | 這台有沒有 Codex。實際是否使用，Core 啟動時會再檢查登入狀態 |
| `workerTimeoutMin` | 否 | 唯讀部下每輪的時間上限，預設 5 分鐘 |
| `dispatch` | 否 | 派工功能（唯讀部下、計畫、Codex 任務、傳訊給同事 session）要不要放進艾莉絲的提示，預設 `false`（艾莉絲以追蹤任務為主）；要派工時設 `true` 再重啟 Core |
| `remoteOrigins` | 否 | 從手機或其他電腦開 Studio 的網址來源，例 `["https://<電腦名>.<tailnet>.ts.net"]`；只收 https。做法見 [手機連線](手機連線.md) |
| `workflowFile` | 否 | 專案卡的流程設定（JSON，路徑相對於 alice.local.json）：幾條進度線、各自的階段、別名、負責的 session、完成條件的角色頁、加進提示的團隊規則。沒設就用內建的「規劃 → 進行中 → 驗證 → 完成」。格式見 [專案管理](spec-projects.md) |
| `translateGlossary` | 否 | 選取翻譯的固定用語，例 `[["pull request / PR", "合併請求"]]` |
| `projects` | 是 | 至少一個專案。缺了它、或缺了 `knowledgeBase` 的三個欄位，知識庫摘要與部下都會停用 |

## `projects[]`

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `name` | 是 | 專案名稱。計畫與對話裡用這個名字指專案 |
| `path` | 是 | 專案資料夾。部下可以唯讀 |
| `role` | 是 | 角色名稱。要和 `rolesDir` 裡的角色頁檔名一致（不含 `.md`） |
| `readDirs` | 否 | 專案外、也讓部下唯讀的資料夾，例如專案紀錄、另一個相關 repo |
| `session` | 否 | 這個角色對應的 Claude Code session 名稱，艾莉絲傳訊與派工時用，例如 `Library`、`<Project> - dev` |
| `writable` | 否 | `true` 時計畫可以派修改類工作到這個專案 |
| `testCommands` | 否 | Core 在每個修改項目前後跑的驗收測試，和開工前比較，沒有新增失敗才算通過。也是 Claude 寫檔 worker 唯一能執行的指令。預設 `["npm test"]` |
| `highRiskPatterns` | 否 | 改到這些路徑時自動加入審查。`*` 不跨資料夾、`**` 可跨；不分大小寫 |
| `forbiddenPatterns` | 否 | 禁止修改的路徑，改到就暫停計畫 |
| `watchPaths` | 否 | git 看不到的路徑（被 `.gitignore` 排除的資料夾、symlink、另一個 git repo），用檔案雜湊或 git 狀態監看，有變動就暫停 |
| `claudeFallback` | 否 | Codex 不可用時：`auto` 自動改由 Claude 寫（預設），`ask` 先暫停問主人 |
| `changeLogDraft` | 否 | `true` 時計畫報告附更改紀錄草稿 |

## 只想先試用

照範例把 `alice-sandbox` 加進 `projects`，指向任何一個有 `npm test` 的小 repo，就能試計畫的修改流程，不會碰到正式專案。

## 和 `ALICE_CONFIG` 的差別

`ALICE_CONFIG` 指向另一份 JSON，用來覆寫 Core 的預設值，例如連接埠、資料夾、模型、逾時；平常不用設定。專案與知識庫一律寫在 `alice.local.json`。
