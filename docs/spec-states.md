# 規格 ②：Character State

> v1.1（2026-09-29 主人確認）。v1.1：釐清精神「低」的時段與 E8 的計數規則。對應規劃紀錄 Q3、Q10。

## 原則

- 狀態由 **Core 依規則決定**；LLM 只讀取（組裝提示時放入），不能直接改狀態。
- 狀態變更時，Core 透過 WebSocket 推送 `state.changed`（見 `spec-protocol.md`）。
- 狀態只有兩個變數：**活動狀態**（4 個）與**精神**（3 級）。

## 變數一：活動狀態

| 狀態 | 代碼 | 意義 | Client 表現（桌寵階段參考） |
| --- | --- | --- | --- |
| 待機 | `idle` | 沒在回覆，也沒有任務 | 待機動畫 |
| 對話中 | `talking` | 正在產生回覆（從收到訊息到回覆結束） | 說話動畫 |
| 忙碌 | `busy` | 有工具任務在執行（階段 A 還沒有工具，先保留） | 工作動畫 |
| 睡覺 | `sleeping` | 閒置過久、深夜，或推理引擎無法使用 | 睡覺動畫 |

`sleeping` 帶一個 `reason`：`idle_timeout`、`night`、`reasoning_unavailable`。

### 優先順序

同時符合時取最前者：`talking` > `busy` > `sleeping` > `idle`。
例：任務執行中，主人又傳訊息，回覆期間是 `talking`，回覆結束後回到 `busy`。

### 事件與轉移

| # | 事件 | 從 | 到 |
| --- | --- | --- | --- |
| E1 | 收到主人訊息 | 任何 | `talking`（若在睡覺＝被叫醒，見 E7） |
| E2 | 回覆結束或失敗 | `talking` | 有任務→`busy`；否則→`idle` |
| E3 | 工具任務開始 | `idle` | `busy` |
| E4 | 最後一個工具任務結束 | `busy` | `idle` |
| E5 | 閒置達 **30 分鐘**（無訊息、無任務） | `idle` | `sleeping`（`idle_timeout`） |
| E6 | 時間進入 **01:00–07:00** 且閒置 ≥ 5 分鐘 | `idle` | `sleeping`（`night`） |
| E7 | 在 `sleeping` 時收到主人訊息 | `sleeping` | `talking`，並記錄「剛被叫醒」供提示使用 |
| E8 | 推理引擎呼叫失敗（連續 **3 次**或驗證錯誤） | 任何 | `sleeping`（`reasoning_unavailable`） |
| E9 | 推理引擎恢復（下一次呼叫成功） | `sleeping`（`reasoning_unavailable`） | 依 E2 規則 |

- E8 計數：驗證錯誤立即觸發；斷線與其他錯誤連續 3 次觸發；成功一次歸零。限流（`rate_limited`）與拒答（`refused`）不計入，走 E2。
- E8 優先於 E2：回覆失敗且符合 E8 條件時，進 `sleeping` 而非 `idle`。
- E8 的狀態下，主人仍可送訊息：Core 照 E1 再試一次推理引擎；成功即 E9，失敗則回傳錯誤 `reasoning_unavailable` 並回到 `sleeping`。Client 顯示「艾莉絲睡著了」，並保留訊息讓主人重送；不會當機（Q10）。
- Core 本身連不上時，由 Client 自行顯示離線，不屬於 Core 狀態。
- 30 分鐘、01:00–07:00、3 次都是暫定值，放在 Core 設定檔，可調。

## 變數二：精神（energy）

影響語氣（見 `persona/alice.md` 說話規則 7），不影響工作模式的準確性。

| 級別 | 代碼 | 規則（Core 計算） |
| --- | --- | --- |
| 好 | `high` | 睡醒後（離開 `sleeping`）的 2 小時內 |
| 普通 | `normal` | 其他時間 |
| 低 | `low` | 22:00～07:00（跨午夜）；或連續對話超過 2 小時（相鄰訊息間隔都小於 30 分鐘的一段，從第一則起算） |

- 同時符合時取 `low`。
- 「心情」暫不另設變數；需要時再加。

## 放進提示的格式

```
[目前狀態] 活動：對話中；精神：好；剛被叫醒：是；現在時間：2026-09-29 08:12（週二）
```
