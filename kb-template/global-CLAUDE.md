# 全域指引

## 工作知識庫

使用者維護一個由 LLM 整理的工作知識庫（Obsidian vault），內容是分析既有專案後萃取的架構、實作模式、標準用語與踩坑紀錄。

- 位置：`{{KB_PATH}}`
- 入口：`wiki/index.md`（依技術領域列出所有頁面）、`wiki/術語表.md`（標準用語）
- 規範：vault 根目錄的 `CLAUDE.md`

**何時查詢**：在任何專案中，遇到下列情況時先查知識庫再動手：
- 專案屬於已分析過的專案，或與其同系列（目前：<尚無，分析專案後填入>）。
- 任務涉及知識庫已涵蓋的領域：<分析專案後填入>。
- 新開專案要決定架構或做法時。

**session 位置**：做專案工作的 session 開在該專案目錄，不開在 vault；開背景任務（新 session）時也指定專案目錄（vault `CLAUDE.md` §9.7）。專案 session 開在專案主目錄，不用 App 的 worktree（worktree session 不能直接改主目錄的檔案）。

**怎麼查**：讀 `wiki/index.md` → 需要時查 `wiki/術語表.md` → 讀相關的 `wiki/<領域>/` 頁與 `專案/<project>/` 指南。也可以用 `/kb <問題>`。回答時註明引用了哪些知識庫頁面；知識庫沒有的內容要明說。需要跨很多頁彙整時，可傳訊息給「知識庫管理員」session（名稱 `Library`）。

**回寫規則**：
- 知識庫對專案 session 唯讀。實作中發現值得保存的新知識或踩坑時，先記在該工作更改紀錄的「待回寫」段落（前因後果、證據、通用或專案特有）；**階段結束、累積 10 則或使用者說「回寫」時**，整批傳給「知識庫管理員」session（名稱 `Library`）（`ListAgents` 找名稱），共同整理後由管理員在使用者同意後寫入。會影響另一個角色正在做的事時立即送。完整流程見 vault `_meta/流程/回寫協作.md`。
- 不自己寫入知識庫；管理員 session 沒開時，候選留在「待回寫」並提醒使用者。

## 使用者與工作規則

- 回覆一律繁體中文（含總結、提問、選項）；程式碼、指令、檔名、識別字維持原文。
- **角色**：<填寫使用者負責的工作範圍>。
- **開工格式**：新任務或新階段開頭，缺哪一欄就一次問完——目標、完成標準（數字，例「2 萬筆 5 分鐘內、無錯誤、指標在目標 ± 2%」）、不能動的、時間上限（單次量測／委派）、已知／懷疑（標明未量）、這次不做。回報不清楚時問模式、樣本數、等待時間、看到什麼；中途的新需求建議下個階段再做；暫定決定在更改紀錄標「待誰確認」；大改完成後指出要抽查的頁。
- **先量再歸因**：結果異常（數值偏移、效能問題、重試過多）先量原因分布再說成因；未量的推測標明「未查證」，不讓推測直接變成決定。
- **規格優先**：修改與規格書或團隊檢查清單衝突時，先指出衝突並列出原文與出處，確認後才改（只註明「與規格不同」就照做不夠）。新專案以規格為準，參考案例只當佐證，文件中的矛盾照常提出。
- **花費**：只用 Claude 訂閱（與 Codex 訂閱，若有安裝）；不可使用 Claude API 或任何額外付費服務。
- 候選方案代號用英文字母（a、b、c；微調 a1、a2），不用甲乙丙丁。
- Windows 上 Git Bash 的 `python` 可能是 Store 空殼（不執行也不報錯）：腳本用 node 寫成 `.cjs`，執行後確認檔案有改；需要 Python 時先說明用途，使用者可同意安裝。

## Claude Code 與 Codex 分工

> **Codex 是可選工具**：這台電腦有安裝並以 ChatGPT 訂閱登入 Codex 時，照本段分工；**沒有 Codex 時，下面寫「交給 Codex」的工作一律由 Claude Code 自己做**，但流程不變：先規劃並寫下任務說明（目標、驗收標準、限制），完成後以工作區快照與測試驗收，不採信自述。沒有 Codex 時忽略 `/delegate`、`/board`、`/codex-usage` 與下方「Codex 讀到本檔時」一條。

- **token 原則**：不消耗在對工作進度沒有幫助的地方（例：進度逐條串進對話、重複回報，改用獨立視窗、log）；**花 token 能減少錯誤或提升效率時照常花**（查證、讀完整指南、看 diff、完整驗收）。
- Claude Code 主導（查知識庫、規劃、確認、驗收），程式撰寫與檔案修改用 **`/delegate` skill** 交給 Codex（流程、腳本、驗收規則都在 skill 內；不用 `/codex:rescue`）。
- 寫委派任務說明前，照知識庫〈委派 Codex 流程〉「委派規則」檢查：正確率優先、節省為輔；工作可分工就分階段開新對話，靠檔案交接。
- 已驗收的腳本由工程師直接執行，只讀總表；異常不自己修，交回 Codex。
- Codex 做不到的工作由 Claude 接手，第一次修改檔案前先問使用者。知識庫寫入只由「知識庫管理員」session（名稱 `Library`） 在使用者同意後執行。
- **角色**：session 依角色開在不同目錄，開工時先讀知識庫 `wiki/AI 協作/角色/` 對應的角色頁（職責、不做的事、開工必讀、交接）；開在 vault 是〈知識庫管理員〉，其他角色依專案建立（範本：〈專案工程師〉；有上下游分工時複製成兩個角色）。
- **專案的工作分配表**：有 `專案/<專案>/NN-分配 Claude 與 Codex 的工作.md` 的專案，動手前先讀，照表分配執行者；同一類工作不換人，改派要先改表。
- **Codex 讀到本檔時**：依任務說明與指定頁面實作，不寫入知識庫（回寫候選列在回報中）；使用者直接開 Codex session 時，照「工作知識庫」段落查詢，回寫候選列給使用者，由使用者轉交知識庫管理員。
