# 委派驗收與工作區快照

> 委派前記錄工作區狀態，結束後以比對結果判斷 agent 實際改了什麼，而不是採信它的自述。由 `agent-snapshot.mjs` 實作，`codex-delegate.mjs` 在 `start` 與 `wait` 時自動呼叫。

## 解決什麼問題

- agent 在既有未提交改動上疊加時，`git diff` 分不出哪些是它改的。
- agent 自述不可靠：曾有 agent 回報二進位檔「未修改」，實際位元組已被改、修改時間也沒變。
- 手動重建基準（套用舊 patch、印整份 diff）輸出量大、容易失敗。

## 做法

**快照（委派前）**：`agent-snapshot.mjs save <repo> <snapDir> [額外檔案]`
- 記錄 `git` HEAD、分支、`git status`。
- 對所有已修改、未追蹤檔案，以及 `--track` 指定檔案計算 sha256，並備份副本到 `{{USERPROFILE}}/.claude/codex-snapshots/<jobId>/files/`。

**比對（委派後）**：`agent-snapshot.mjs diff <snapDir>`，只輸出摘要：
| 分類 | 意義 | 驗收動作 |
| --- | --- | --- |
| 新增（未追蹤） | agent 新建的檔案 | 確認都在任務範圍內 |
| 修改（快照時乾淨） | 原本沒改動的檔案被改 | 看 `+/-` 行數，必要時只看該檔 diff |
| 修改（指定追蹤檔） | `--track` 的檔案 sha256 改變 | 二進位檔要再比內容 |
| 原本已有未提交改動、又被修改 | 可能動到使用者既有的工作 | **逐一確認** |
| 刪除 | 快照中的檔案不見 | **逐一確認** |
| HEAD / 分支改變 | agent commit 或切分支 | 違反委派規則，回報使用者 |

驗收步驟：
1. 讀比對摘要，以它為準。
2. 確認任務指定的測試結果，只看結果摘要。由誰重跑依專案的工作分配表（建議：工程師執行已驗收的腳本、只讀總表）。
3. 對照基準狀態：原本就失敗的測試，失敗內容要與委派前相同。
4. 正在執行的 dev server / App 需要重啟才能反映改動時，提醒使用者。
5. 有副作用時回報，並提議以快照副本還原（還原會覆寫檔案，要先問使用者）。

## 取捨

| 優點 | 缺點 |
| --- | --- |
| 能抓到 agent 沒回報的副作用 | 大量未提交二進位檔時，快照副本占空間 |
| 可直接用副本還原 | 建置產物、執行中程式的狀態不在比對範圍 |

## 注意事項

> [!danger] 注意
> - 值相同不代表檔案沒變：二進位檔要同時做內容比對與位元組比對。
> - 快照只涵蓋 git 工作區；`.gitignore` 內的檔案不在比對範圍，要另外檢查。
> - 快照只比對委派 cwd 所在的 repo；Codex 改到 repo 外的檔案時，比對摘要不會列出，要另外看 diff。
