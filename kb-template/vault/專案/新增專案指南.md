# 新增專案指南

> 把一個新專案加進知識庫時的步驟與資料夾範本。分析流程本身見 [[_meta/流程/分析專案]]；本頁只說明 `專案/<專案>/` 底下要建立哪些頁。

## 步驟

1. 和使用者確認範圍：專案路徑、分支與 commit、這次要涵蓋的模組（第一次分析一定要確認）。
2. 建立 `專案/<專案>/00-總覽.md`（模板 `_meta/templates/專案總覽頁.md`）：用途、基本資訊（repo 路徑、分析版本 `basis`、技術棧）、架構速覽、操作指南表（「我要… → 指南」）、常用指令。
3. 依「要完成某件事時該怎麼做」撰寫指南頁 `NN-動詞開頭的任務名.md`（模板 `_meta/templates/指南頁.md`），每頁 frontmatter 加 `project` 與 `basis`。
4. 專案有固定的 Claude／Codex 分工時，建立 `NN-分配 Claude 與 Codex 的工作.md`：工作項編號、範疇、執行者（C／X／U）、產出，以及例外處理與變更紀錄（見 [[Claude Code 與 Codex 分工]]）。
5. 需要專屬角色時，複製 `wiki/AI 協作/角色/專案工程師.md` 範本改成具體角色（有上下游分工時複製成兩個），並在分工頁「角色」表登記。
6. 最後建立 `99-注意事項與待確認.md`：風險清單（🔴🟠🟡）與待確認事項。
7. 通用知識寫到 `wiki/<領域>/`（新領域先問使用者），並更新術語表、`wiki/index.md`、`wiki/overview.md`、[[艾莉絲摘要]]，在 `wiki/log.md` 記一筆 `analyze`。

## 資料夾範本

```text
專案/<專案>/
├── 00-總覽.md
├── 01-建立開發環境.md
├── 02-<任務>.md
├── NN-分配 Claude 與 Codex 的工作.md   （選用）
├── <流程群>/<分組>/<前綴>-<流程名>.md    （選用，分支流程頁，見 CLAUDE.md §3.4）
└── 99-注意事項與待確認.md
```

## 注意事項

> [!danger] 注意
> - 被分析的 repo 一律唯讀，除非使用者明確授權。
> - 某件工作的數據與進度寫在知識庫外的工作紀錄，專案指南只寫流程、順序與注意事項，並寫紀錄檔路徑。
> - 連到 `00-總覽`、`99-注意事項與待確認` 時一律寫完整路徑（`CLAUDE.md` §3.1）。
