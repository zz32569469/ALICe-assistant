# 撰寫分支流程頁

> 執行這個流程前先讀本頁。規範仍以 `CLAUDE.md` 為準，修改本頁與修改 Schema 相同，要在 `wiki/log.md` 記一筆 `schema`。

一件大工作（例：建立一個新模組）拆成多條可單獨執行的分支流程時使用。
- 位置：`專案/<project>/<流程群>/<分組>/`；入口頁 `<前綴>-流程總覽` 放在流程群根目錄。分類沿用 §3.2「子資料夾 + tag + 頁面關聯」。
- 命名：`<前綴>-<流程名>`（例 `新模組-資料結構`），**不用 `NN-` 編號**，因為分支流程之間沒有執行順序。
- 類型：`type: guide`，模板 `_meta/templates/分支流程頁.md`。章節：引言 → 適用情境 → 前置知識 → 輸入契約 → 步驟 → 產出契約 → 涉及檔案 → 驗證方式 → 注意事項 → 相關。
- frontmatter 另加 `up`（入口頁）、`related`、`requires` / `requires_optional` / `provides`（契約項目 ID）。`requires` 只放硬性前提；啟用某個選用功能時才需要的輸入放 `requires_optional`，並在內文輸入契約標「（選用）」與成立條件。入口頁契約表的「提供者 / 使用者」欄由各頁 frontmatter 產生，不手寫。
- **契約式獨立**：流程內不寫「先完成 X 流程」，只寫輸入契約（需要哪些資料已存在、怎麼確認）。契約項目 ID 以入口頁的「契約項目表」為唯一權威，ID 用程式中的資料路徑（`define.window`、`result.prizes.<key>`），非程式資料用 `類別:名稱`（`git:tag`）。
- 步驟表標示執行者（需求方 / 開發者 / Claude / Codex）與可否委派 Codex。
- 原理只連到 wiki；既有 `NN-` 操作指南保留，分支流程的步驟連過去。
