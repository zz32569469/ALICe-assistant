# codex-usage：Codex 用量與額度

資料來源：`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`（每個 Codex 對話一個檔；`token_count` 事件記累計用量與額度）。只讀，不花 Codex 額度。

## 步驟

1. **總表與額度**
   ```bash
   node ~/.claude/skills/codex-usage/scripts/usage.cjs [--since YYYY-MM-DD] [--until YYYY-MM-DD] [--cwd <路徑片段>]
   ```
   預設從昨天到今天。輸出每個對話的開始時間、目錄、任務標題（任務說明的第一個 `#` 標題）、指令數、輸入 token（含快取）、未快取、輸出、最大對話長度，以及最新一筆的短期／每週額度與重置時間。

2. **拆解貴的對話**（需要時）：挑總表中輸入最多的幾個，傳檔名的時間片段：
   ```bash
   node ~/.claude/skills/codex-usage/scripts/breakdown.cjs 2026-09-24T10-23-53 2026-09-24T10-59-07
   ```
   把「每一步新加入的內容 × 之後重送的輪數」歸到指令類型：固定開頭、讀檔／搜尋、執行腳本／測試、臨時內嵌腳本、改檔、git、其他。

3. **回報**：
   - 額度：已用百分比與重置時間；剩餘不多時建議只委派需要寫程式的工作。
   - 依任務類型彙總（同類任務合計、占比、每個任務的範圍）。
   - 最貴的來源與具體原因（例：輸出整份 JSON、必讀頁讓開頭變長、反覆查看長時間指令的進度），對照知識庫〈委派 Codex 流程〉的委派規則提出改善。
   - 標題為 `-` 的對話不是透過 `/delegate` 委派的（使用者自己開的或其他工具），請使用者確認來源。

## 判讀
- 花費 ≈ 指令數 × 當時的對話長度；「最大對話長度」高、指令數多的對話最貴。
- 「未快取」才是新送出的內容；快取部分仍會計入額度，但量級看「輸入」即可。
- 拆解是估算：增量歸給該步的指令，模型思考併入其中，不單獨列出。
